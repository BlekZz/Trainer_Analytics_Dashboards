# 模組 C：教學機制設計 (Pedagogical Mechanics)

> **核心原則：訓練型 dashboard 的價值不在「答案是否正確」，而在「思考路徑是否被引導」。**

---

## C.1 二維難度矩陣

```
           ┌─────────┬─────────┬─────────┐
           │   L1    │   L2    │   L3    │
           │  單圖   │ 同頁跨圖 │ 跨頁交叉 │
   ────────┼─────────┼─────────┼─────────┤
   F       │  L1·F   │  L2·F   │  L3·F   │ 純擷取資料事實
   只需事實 │ 讀數題  │ 對比題  │ 串接題   │
   ────────┼─────────┼─────────┼─────────┤
   F+I     │  L1·I   │  L2·I   │  L3·I   │ 事實+推論
   含推論   │ 解釋題  │ 推因題  │ 預測題   │
   ────────┼─────────┼─────────┼─────────┤
   F+I+A   │  L1·A   │  L2·A   │  L3·A   │ 含假設陳述
   含假設   │ 提問題  │ 設計題  │ 策略題   │
   ────────┴─────────┴─────────┴─────────┘
```

### L 軸定義（資料覆蓋範圍）

| 標籤 | 定義 | 視覺色（chip） |
|---|---|---|
| **L1** | 答案只需要看「一張圖」就能得出 | 淺藍 `#e3f2fd` / `#1565c0` |
| **L2** | 答案需要看「同一頁的多張圖」交叉 | 橘 `#fff4e0` / `#a36a08` |
| **L3** | 答案需要跨「不同頁面」的圖表串接 | 紅 `#fde7e3` / `#a8362a` |

### F/I/A 軸定義（認知深度）

| 標籤 | 答案結構 | 視覺色（chip） |
|---|---|---|
| **F (Fact)** | 只需 📊觀察 | 藍 `#dbe7ff` / `#1a3a99` |
| **I (Inference)** | 📊觀察 → 🧠推論 | 黃 `#fef4d9` / `#8a5d00` |
| **A (Assumption)** | 📊觀察 → 🧠推論 → 🎯行動 + ⚠陷阱 | 紅 `#fde7e3` / `#a8362a` |

### 標題列實際呈現

每題標題開頭有兩個並列 chip，例如：

```html
<div class="qa-q-text">
  <span class="qa-level l2">L2</span>
  <span class="qa-depth a">A</span>
  Q4 答案：給定 X 假設，你會優先處理哪一個會員等級？
</div>
```

## C.2 答案三段式結構

依 F/I/A 深度決定要寫到第幾段：

### F 題（只到觀察）

```
📊 觀察：從〔圖名〕的〔具體位置〕可看到，X = 數值 / Y 在 Z 區段呈現 W 模式。
```

每句話的數字都要能反推 — 例如「10 月流失峰 985 人」必須真的從 DATA.member_flow.loss[9] = 985 得出。

### I 題（觀察 + 推論）

```
📊 觀察：[事實陳述]
🧠 推論：[F] 圖示...；[I] 推測背後成因 / 影響範圍 / 趨勢延伸
```

推論句必須**明確標 F/I 字母**：

```
<span class="fia f">F</span> 流失人數 985 是全年最高
<span class="fia i">I</span> 推測對應促銷期結束後的低黏性用戶離開
```

### A 題（觀察 + 推論 + 行動 + 陷阱）

```
📊 觀察：[事實]
🧠 推論：[F] ...；[I] ...；[A] 但若沒有 X 資料驗證，此解釋仍是假設
🎯 行動：(1) 需要哪些補充資料；(2) 設計什麼干預；(3) 監控什麼指標
⚠ 陷阱（trap-block）：這題實習生最常犯的錯誤推論
```

A 題必須包含 **`<span class="fia a">A</span>`** 標註，明確告訴學員「這段不是事實也不是合理推論，是需要被驗證的假設」。

### [A] 標籤的嚴格使用規則（不限 A 題）

**任何答案段落中出現「不在 DATA 物件裡的數字」，都必須掛 [A] 標籤，即使題目本身是 I 題。**

常見需要 [A] 的情境：

| 情境 | 範例 | 正確做法 |
|---|---|---|
| 估算平均頻次 | 「若VIP年均32次」 | [A] 標記 + 說明「此頻次為假設值，非原始資料」 |
| 外推未來趨勢 | 「若維持成長率，Q3 將達 5,000」 | [A] 標記 + 說明「外推假設趨勢不變」 |
| 引用外部業界數字 | 「業界外送抽成約 20%」 | [A] 標記 + 說明「此為業界估算，非本資料集的數字」 |
| 跨系統口徑推算 | 「若 LTV 按常見公式計算」 | [A] 標記 + 說明計算假設 |

**反模式**：把估算數字放在 [I] 段落，不加 [A] — 學員會誤以為是從圖表讀出的事實。

**正確分段範例**（I 題中夾帶估算）：

```html
<p><span class="tag-i">I:</span> 高頻顧客頻率遠高於常客，年度LTV應顯著更高。</p>
<p><span class="tag-a">A:</span> 估算示意（頻次為假設值）：若VIP年均32次、AOV=271，
  年LTV≈ NT$8,672；此估算僅說明原理，實際頻次需從門市記錄計算。</p>
```

### 三段式 vs F/I/A 的對應關係

```
┌──────────────┬────────┬────────┬────────┐
│ 段落         │   F    │   I    │   A    │
├──────────────┼────────┼────────┼────────┤
│ 📊 觀察      │ ✓ 必須 │ ✓ 必須 │ ✓ 必須 │
│ 🧠 推論      │   ✗    │ ✓ 必須 │ ✓ 必須 │
│ 🎯 行動      │   ✗    │ 選用   │ ✓ 必須 │
│ ⚠ 陷阱       │   ✗    │   ✗    │ ✓ 必須 │
└──────────────┴────────┴────────┴────────┘
```

## C.3 證據碼引用規範

答案中所有提到的圖表都要用 `<span class="ev">` 標註，讓學員一眼看出**這個推論的根據是哪張圖**。

```html
從<span class="ev">每月新增 vs 流失圖</span>的紅色柱可看到，
流失人數從 7 月的 758 人起持續攀升...
```

CSS：
```css
.ev {
  display:inline;
  background:rgba(45,91,227,0.09);
  border-radius:4px;
  padding:1px 5px;
  font-family:'JetBrains Mono',monospace;
  font-size:11.5px;
  color:var(--accent);
  font-weight:500;
}
```

**規則**：
1. 每個具體數字後面必須有 `<span class="ev">` 引用來源圖
2. 不要寫「根據資料顯示」這種模糊歸因
3. 跨頁引用要搭配 nav-hint 卡片

## C.4 陷阱區塊（Trap Block）設計

每個 A 題與所有訓練題必須有「常見陷阱」紅色區塊，揭露**實習生最容易犯的錯誤推論**。

```html
<div class="trap-block">
  <span class="trap-label">⚠ 陷阱</span>
  <strong>常見錯誤推論：</strong>實習生看到 KPI 與圖表的小差距會慌張改數字。
  但<strong>合理的口徑差異是業界常態</strong>，重點不在「消滅差距」，
  而在「能解釋差距」並把口徑寫清楚。
</div>
```

### 陷阱主題庫（依產業可選）

通用陷阱：
1. **倖存者偏誤** — 「只看有購買者的特徵」推論「所有人都該被這樣對待」
2. **相關 vs 因果混淆** — 「兩個指標同時上升」推論「彼此互為因果」
3. **過度集中推論** — 「年齡分佈集中 + 渠道分佈集中」推論「年輕人都來自社群」
4. **平均數陷阱** — 「人均 X」推論「每個人都 X」（忽略內部變異）
5. **基線缺失** — 沒有對照組就下結論
6. **量級錯置** — 把「日均 / 月均 / 年總」混為一談
7. **百分比錯置** — 「分母用錯」（佔有購買者 vs 佔總會員是兩種數字）
8. **口徑差焦慮** — 「KPI 跟圖表差 2%」就懷疑資料錯（其實是定義差異）

### 不同產業的特化陷阱

| 產業 | 特化陷阱 |
|---|---|
| 電商 | 退貨率 / 取消單 / 試衣間訂單未過濾 |
| SaaS | DAU/MAU 比值誤讀、轉換漏斗階段定義 |
| 餐飲 | 翻桌率 vs 客數混淆、外帶 vs 內用合併 |
| 教育 | 註冊 ≠ 啟用 ≠ 完課，三者比例懸殊 |
| 訂閱媒體 | 試用期用戶 vs 付費用戶區分不清 |

## C.4b 三條不可違反的分析基準原則

這三條優先級高於所有其他設計選擇，不受差異化策略影響。

### 原則 1：所有分析依據只使用儀表板呈現的數據

**答案的 F/I 段落中引用的每一個數字，必須能在儀表板圖表或 DATA 物件中找到原始出處。**

| 違規範例 | 正確做法 |
|---|---|
| F tag 說「前5名品項貢獻60%業績」但儀表板只有品類數據 | 改說「套餐品類佔42%業績（品類圖）」 |
| I tag 推論「SKU 層級集中度更高」 | [A] tag 標記：「若細拆至SKU，集中度可能更高（假設）」 |
| 引用業界均值比較「業界標準回購率約45%」 | [A] tag 標記：「以業界估算值（假設）相比」 |

計算出的指標（如 HHI）必須能從儀表板顯示的數據反推，否則只能以「品類層級」、「估算」等明確限定語呈現，並說明計算方式。

### 原則 2：所有縮寫與專有名詞必須在指標定義面板中定義

**儀表板中出現的每一個縮寫、指數名稱、分析術語，都必須在指標定義面板（def-panel）中有條目。**

必須定義的術語類型：
- 財務/行銷縮寫：YoY、pp、LTV、ROI、KPI、AOV、ARR、NPS 等
- 業界指數名稱：HHI（需含全名 Herfindahl-Hirschman Index）、Churn Rate 等
- 方法論術語：Cohort、Funnel、CAC 等

檢查方式：搜尋整份 HTML 中的所有大寫縮寫（2-5 個英文字母），逐一確認 def-panel 有對應條目。

**反例（禁止）**：KPI 卡顯示 `+5.1pp YoY` 但 def-panel 沒有 pp 和 YoY 的定義。

### 原則 3：F/I/A 標籤系統必須在儀表板可見位置有說明

學員必須在打開第一道答案之前就能看到 F/I/A 的含義說明。兩種實現方式（擇一或合用）：

1. **Legend strip**：在頁頂顏色圖例條中直接加入 `F 事實` / `I 推論` / `A 假設` 標籤元素
2. **def-panel 獨立條目**：新增「F/I/A 答案標籤系統」條目，說明三者的定義與區分

不可只在答案摺疊區內部使用，因為學員必須先展開才能看到——那是「知道後才能理解」的機制，不是說明機制。

## C.5 nav-hint 設計規範

跨頁推論題（L3 系列）的答案區必須有 nav-hint：

```html
<div class="nav-hint" onclick="switchPage('cross','cTierSpend')">
  <span class="nh-arrow">👉</span>
  <div class="nh-body">
    <span class="nh-label">需切換到「🔗 交叉分析」→「各等級年均消費比較圖」</span>
    <span class="nh-sub">用各等級的年均消費精算營收貢獻，才能評估流失衝擊</span>
  </div>
</div>
```

**規則**：
1. 一題最多兩個 nav-hint（再多會分散注意力）
2. 必須在 `.qa-answer` 內，**摺疊狀態下隱藏**
3. label 要說「為什麼需要切到那張圖」而非只說「請看 X 圖」
4. onclick 必須 trigger flash-target 動畫，視覺強化跳轉

## C.6 KPI 卡片教學設計

KPI 卡是學員第一個看到的，要設計成「有故事的數字」：

| 必備元素 | 範例 |
|---|---|
| 主數字 | `48,263 人` |
| 對比基準 | `vs 42,939 (2023)` |
| 變化方向與幅度 | `↑ +12.4% YoY` |
| 業務含義一句話（可選） | `較去年惡化` / `穩定集中` |

**反設計建議**：故意在 KPI 卡留下「需要被質疑」的線索：
- 「+12.4% YoY」但圖表淨增是 5,412 人 — 留下「合理口徑差」當 Q2 教學點
- 「高頻 22.3% 貢獻 67% 交易額」— 留下「集中度風險」當訓練題切入點
- 「年流失率 18.3%」— 留下「流失定義是什麼」當定義面板的教學點

KPI 卡不是答案，是**讓人想質疑的起點**。

## C.7 訓練題（Training Questions）設計

P3 結尾必設「實習生綜合訓練題」區塊（紫色 panel）。一般有 3-5 道，全部是 L3·A 級別的開放題：

```
T1. [策略決策題]
    例：「如果你是 PM，你會優先改善哪個會員等級的流失問題？為什麼？」
    答案結構：① 結論先行 → ② 數據佐證（多個 ev 引用）→
              ③ 對照否定論點 → ④ 行動建議 → ⑤ 陷阱

T2. [取捨權衡題]
    例：「社群 LTV 最低但量最大，放棄還是優化？」
    答案結構：① 兩面論述都要陳述 → ② 用第三維度（CAC、產業基準）做決
              策 → ③ 給「不選擇」的代價分析

T3. [集中度/風險題]
    例：「22% 用戶貢獻 67% 交易，是好現象還是警訊？」
    答案結構：① 雙重視角必備 → ② 計算具體衝擊 → ③ 補救池識別

T4. [缺失維度題] ← 必設
    例：「這份 Dashboard 還缺哪些分析視角？至少提 3 個。」
    答案結構：列 5 個（3 個明顯 + 2 個進階）
```

訓練題的視覺：用紫色系（與一般 QA 區分），icon 是 `★` 而非 `A`。

## C.8 📐 設計選擇揭露區塊（D12）

P3 最末必設「設計選擇揭露」橘色 panel（`.meta-panel`）。揭露 8 個設計決策，**每項必須從以下三個分析維度說明**（並非每項都需要三維，但至少涵蓋其中兩個）：

| 維度 | 核心問題 | 禁止寫法 |
|---|---|---|
| **分析資料選擇** | 為什麼用這幾個指標來看什麼商業問題 | 「為了讓學員了解…」 |
| **視覺設計邏輯** | 為什麼這個視覺形式適合呈現這份資料 | 「為了讓圖表更清楚…」 |
| **閱讀設計** | 讀者應看到什麼、帶走什麼判斷或認知 | 「為了讓學員練習…」 |

### 標準 8 個決策主題（可依產業調整措辭）

```
1. 分頁 vs 單頁 — 為何分成 N 個分頁分析視角
2. KPI 卡位置 — 為什麼放最上面，以及為什麼「先看圖再看 KPI」是更好的習慣
3. 特定圖表類型選擇 — 為什麼用 X 圖而非 Y 圖（針對最有爭議的圖）
4. 策略閾值標示 — 為什麼把某個門檻畫在圖上
5. 刻意排除資料 — 為什麼某張圖不畫某個數據（視覺工程決策）
6. 刻意缺席的指標 — 為什麼不放某些維度（分析邊界決策）
7. 難度分層 L1/L2/L3 — 對應分析師實務的三種認知負荷
8. F/I/A 標註 — 論述強度標示的意義，不是只為了好看
```

### intro 文字範本

```
每一個圖表與儀表板設計背後都有三個問題：用哪些指標回答什麼商業問題？
這個視覺形式為什麼適合這份資料？讀者應該看到什麼、帶走什麼判斷？
以下逐一說明本儀表板的 8 個關鍵設計決策。
```

### 維度標籤 HTML 格式（在 `<p>` 內用 `<strong>` 標記，維度之間加 `<br><br>`）

```html
<p><strong>分析資料選擇：</strong>...說明用哪些指標解決什麼問題。<br><br>
<strong>視覺設計邏輯：</strong>...說明為什麼用這個視覺形式。<br><br>
<strong>閱讀設計：</strong>...說明讀者應讀到什麼判斷。</p>
```

**這是整份儀表板最有分析價值的區塊**——揭露「儀表板本身也是被設計出來的，每個元素背後都有商業分析邏輯」。

## C.9 題目分佈建議

依訓練主題不同，建議分佈：

| 主題類型 | L1·F | L1·I | L1·A | L2·F | L2·I | L2·A | L3·F | L3·I | L3·A | 訓練題 |
|---|---|---|---|---|---|---|---|---|---|---|
| **入門型**（會員結構分析） | 3 | 3 | 2 | 1 | 2 | 1 | 1 | 1 | 1 | 3 |
| **進階型**（cohort 留存） | 1 | 2 | 1 | 2 | 3 | 2 | 1 | 2 | 2 | 4 |
| **批判型**（A/B test 解讀） | 0 | 1 | 2 | 1 | 1 | 3 | 0 | 2 | 4 | 5 |
| **平衡型**（前一輪用此） | 2 | 3 | 1 | 1 | 2 | 1 | 1 | 2 | 2 | 4 |

**分佈不該全在對角線**（純 L?·F 或純 L3·A），要有「橫向反差」：
- **L1·A**（少資料深推論）— 訓練「在資料不足時也能提出有意義的問題」
- **L3·F**（多資料淺擷取）— 訓練「從多個圖中提取與整合具體事實」

## C.10 教學反模式
